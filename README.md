# Planning Poker на Timeweb

Фронтенд и API теперь запускаются одним Node.js-приложением на Timeweb. Браузер отправляет запросы на `/api/poker` с того же адреса, где открыт сайт: запросов к `chatgpt.site` и CORS-preflight больше нет. Комнаты хранятся в PostgreSQL.

## Развернуть

1. Создайте облачную базу PostgreSQL в Timeweb Cloud и скопируйте строку подключения из раздела «Подключение».
2. В App Platform создайте **Backend-приложение** из ветки `main` этого репозитория. Выберите Node.js 22 или 24 и команду запуска `npm start` (если Timeweb не определит её сам). Новое приложение получит свой технический адрес; именно его нужно будет отправлять пользователям.
3. Добавьте переменную `DATABASE_URL` со строкой подключения PostgreSQL.
4. Дождитесь деплоя и откройте `https://<адрес-приложения>/healthz`. Ответ `{"ok":true}` означает, что приложение запустилось и подключилось к БД. Главная страница и API работают на этом же адресе.

В App Platform локальные файлы контейнера удаляются при новом деплое, поэтому база SQLite в файле там не подходит. PostgreSQL сохраняет комнаты между деплоями. Приложение раздаёт сайт и API с одного адреса, так что браузеру не нужен CORS.

## Перенести существующие комнаты

Экспорт старых комнат хранится локально в `rooms-export.json` и исключён из Git. После создания PostgreSQL выполните на компьютере в папке проекта:

```sh
npm install
DATABASE_URL='строка-подключения-из-Timeweb' npm run import-rooms
```

Скрипт добавляет только отсутствующие комнаты, повторный запуск не перезаписывает уже перенесённые данные. Не отправляйте `rooms-export.json` в Git: внутри сохранены данные текущих комнат.

После успешного запуска App Platform переключите ссылку на сайт на новый адрес приложения. Пока новый backend не развёрнут с настроенной БД, существующая публикация не меняется.
